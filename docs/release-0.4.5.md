# 0.4.5：空白欄與公告操作

比賽安排可直接按「＋ 新增空白欄」，也能用表格邊界的「＋」插入指定位置。不用先選級數，標題可自行修改，資料格可放選手或文字。原有欄位、選手位置、列印樣式及會員分級不重排。

## 安排表格

- 選手移入普通空白欄只換位置，保留該人的本場級數；移入既有級數欄，維持原有的本場調級行為。交換時各自依目的欄處理。
- 普通欄中的選手更改餐食或明確調級後保留位置。新增正取與候補遞補仍依原有級數定位規則；缺少需要的級數欄時由寫入交易補回。
- 表頭、文字格與合併區不能放選手；含選手的欄仍須先移走選手才能刪除。會員級數與報名時的級數快照不會被表格操作回寫。
- 復原與重做同時核對伺服器保存的位置及本場級數，保留操作紀錄與版本遞增；遇到其他管理員更新或保存基準變動，必須重新核對。

## 公告

新公告先儲存為未公開，再使用「公開到首頁」與「置頂公告」開關。開關會立即保存狀態；有未儲存內容時先停用，避免公開操作一起送出尚未完成的草稿。已公開公告再次儲存內容會更新首頁，畫面會明確提示。

「公告修改歷史」位於儲存按鈕下方，公開與置頂位於桌面右側、手機下方。公告清單限寬，編輯區及工具列留白增加。中文斜體允許瀏覽器在沒有斜體字型時合成字形，儲存後與公開內文一致。刪除、還原、圖片、衝突及結果不明時的原樣重試沿用既有保護。

## 相容與升級

SQLite schema 延用 0.4.4 的 `0013_announcement_deletion`。從 0.4.3／0012 更新，須先停寫並成組備份資料庫與媒體，再透過 runtime guard 明確執行 migration；啟動不會自動初始化或遷移。既有資料與帳號保留，公告新增的刪除時間預設為空。

表格 JSON 新增 schema 2，僅在支援新版的成功寫入交易升級；讀取及資料庫 migration 不改寫舊布局與歷史。新版前端送出明確的布局能力版本，已升級安排會拒絕舊分頁的表格操作（grid operation）新寫入並要求重新整理；原請求仍可核對既有收據。

使用新空白欄後，不能直接退回只理解 schema 1 的舊程式。需要回復時保留目前資料，以匹配映像與升級前備份還原到新目標，不覆寫故障庫。前後端需同批更新。部署流程見[部署手冊](deployment.md)。
