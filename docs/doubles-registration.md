# 雙打報名與管理

建立比賽時可選「個人報名」或「雙打組隊」。模式建立後不可更改；原個人賽仍使用既有報名、餐食與級數安排。雙打名額以隊計，不提供餐食或級數安排表。可設定兩人登記級數合計至少 2–20 級，預設 10，留空表示不設門檻。

公開頁提供「我先報名，等待搭檔」與「我們兩人一起報名」。搜尋姓名時請核對辨識註記；同名會員以不同會員 ID 識別。等待名單的「和這位組隊」會帶入第一位會員，選第二位後再次顯示兩位姓名與註記。請先與搭檔說好，也可請親友代報；更正請洽管理員。

單人列為等待搭檔，兩人列為待管理員確認，都不占正式隊數。由等待名單組隊時承接原登記級數；兩人合計低於門檻仍能送出及接受，畫面以文字提醒管理員。名單區分等待搭檔、待確認、正取與候補。公開頁不提供取消、拆隊或移走已成隊會員的功能。報名截止後表單隱藏，首頁仍可進入雙打名單。

管理員在雙打比賽看到專用名單，可新增一人／兩人、接受報名、取消、拆回等待搭檔，以及依序遞補最早候補。接受時若沒有名額或已有候補，整隊加入候補。取消不自動遞補。更換搭檔請先拆隊，再新增兩人組隊並接受。取消與拆隊必須填原因；截止後新增、接受與遞補也必須填原因。已結束、取消、刪除及草稿比賽唯讀。

「已取消」以筆計，包含已組隊或拆隊後保留的舊登記。操作紀錄以中文顯示操作、會員、管理員／公開訪客、時間與原因。級數是登記快照，不回寫長期會員級數。

## 寫入與錯誤恢復

寫入結果未知時，整個雙打操作鎖定，保留原請求編號與會員／版本／原因，使用「原樣重試並核對結果」。安全挑戰需要重新驗證時，只更新 Turnstile token，保留業務內容及原請求編號。一旦結果未知，之後身分失效、限流或其他錯誤仍保留原操作；公開訪客請聯絡管理員，管理員可在另一分頁以原帳號登入後重試，系統會核對原帳號。

取得成功回執後若名單讀回失敗，只重新 GET，不再次提交 POST。初次已知 409 衝突要求更新名單後重新決定，保留表單草稿且不顯示成功訊息。管理原因依原登記 ID 與操作分別保留；讀回後重新選相同操作可帶回原因，仍須由人明確再次提交，成功後才清除該操作草稿。管理端讀取與寫入互鎖，避免較早的讀取蓋過新名單。尚未確認的操作須保留此分頁；重新整理或關閉分頁不會保存記憶體中的未確認請求，請先由管理員核對。

## 升級與驗證範圍

API 契約見 [doubles-registration-api.md](doubles-registration-api.md)。新增 migration `0014_doubles_registration`，舊比賽預設為個人賽。前後端須同批更新；正式資料升級須另行授權，依既有停寫、備份及 maintenance 流程操作。降版必須使用匹配 image/schema 與備份還原流程，不能直接換回舊 app。

本輪僅使用合成測試資料、獨立 port `8057`、`data/doubles-registration-e2e.db`、`frontend/dist-doubles-e2e`。真實資料、發布、部署、公開 Tunnel 與原預覽不在此次範圍。E2E 使用隨機測試密碼並關閉 trace，測試涵蓋桌面／手機及根路徑／`/fucheng`；實際結果與截圖請見本輪 task report。
