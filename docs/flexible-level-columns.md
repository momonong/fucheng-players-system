# 場次級數欄自由調整

2026-10-05：使用者確認「先移走選手再刪欄」。0.3.9已合併、發布映像並部署4090；資料保留與公開讀取驗證通過。實際上線結果見[部署紀錄](home-deployment.md)。

## 行為

- 每場預設仍從十級開始，既有安排不自動改寫。空的級數欄可從欄邊 ⋯ 刪除；有人先移走，含自訂文字需確認，至少保留一個級數欄及一排資料格。
- 刪欄只調整當場布局，不刪會員／報名，不改剩餘選手的格位、版本或級數。原文字確認、合併區保留、底色清理、token 衝突及固定請求重試沿用。
- 表格上方「加回級數欄」列出未使用級數，加回後附加在最右側並使用新 stable ID，不擠入既有合併範圍。要完整還原剛才的刪除，可用原復原／重做。
- 新正取、遞補、調級或移到欄底用到缺少的級數時，與原寫入同交易補回；GET 不補欄。文字欄最多40個，保留補齊級數所需容量，總欄數仍最多50。
- 表格寬度依實際欄數計算；完整保存、唯讀歷史、PDF 列印及 Excel 都依快照 columns 呈現。會員級數、報名快照和當次級數仍保持獨立。

## 相容性與驗收範圍

無資料表 migration，schema 仍 `0010_deployment_report`。JSON 級數欄可為子集合，新 operation 為 `add_level_column`；前後端需一起更新。使用精簡欄位後，舊版要求十欄的 app 不再能直接無損回退；優先向前修正，需回復時遵守匹配備份／新目標與保留後續資料的既有流程。

功能開發階段沒有改正式資料、Docker、HP／ASUS、Caddy、Tunnel 或 DNS；後續發布部署另記於日期化紀錄。手機真機使用手感仍待部署後由使用者試用。
