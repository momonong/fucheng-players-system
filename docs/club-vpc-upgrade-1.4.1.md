# 球館升級至 1.4.1

目前為 1.3.0 或 1.4.0 的球館，可使用 [v1.4.1 Release](https://github.com/momonong/fucheng-players-system/releases/tag/v1.4.1) 附件 `update-club-v1.4.1.ps1`。將整段貼進球館 PowerShell，工具會自動下載固定來源並驗證腳本與映像。

## 原帳號、資料與收據

更新器逐項核對原始 1.2 部署收據、已完成的 1.2→1.3 收據，以及現有的 1.3→1.4 收據。每份收據核對部署 ID、映像 pin、操作 ID 與成功狀態、資料及媒體摘要、管理員數及原 Compose／owner 副本。未知或未完成的操作會停止流程。

停寫後使用原版本建立新備份。換用 1.4.1 後，比對所有資料表與媒體摘要，包含原管理員和登入 session，一致才接通原 Tunnel，最後確認公開健康。請沿用原帳密登入。

## 備份輪替

週備份設定由八組改成兩組，在下一次新週備份成功後縮減。升級前備份在本次升級完成且網站健康後輪替，保留最近兩組通過驗證的完整副本。

只有舊組內的資料庫、媒體封存與備份描述檔會被清理。升級收據、原 Compose／owner 副本與操作容器紀錄都會保留。無法驗證或不完整的備份會保留並提示。清理失敗時可保留部分檔案供維護者檢查。

部署前檢查點、獨立手動備份、還原前備份及匯出檔由管理者保管。收據目錄內保留的小型紀錄仍會隨升級次數增加。

## 失敗與重跑

看到停止訊息時，回傳階段與代碼。保留原請求 ID、操作容器、備份及收據，核對結果後由維護者處理。部分切換失敗會逐一停止已核對身份的寫入容器。

已完成本次升級的重跑，會核對目標身份、資料卷使用者及公開健康，再補做中斷的備份輪替。原升級收據繼續保留。舊收據的備份已輪替後，仍可依保留的收據與 Compose 副本核對歷史。

新版更新器為 `deploy/docker/club-vpc-upgrade-retention.ps1`。正式指令所使用的 commit、腳本 SHA256、映像 digest 與 config ID 列於 Release，球館以該固定指令更新。
