# 0.4.4：公告可還原刪除

管理員可在「公告管理」刪除及還原公告，保留已儲存的本文、照片、內文圖片與操作紀錄。一般下架仍沿用原有「發布到首頁」勾選，不必刪除公告。

## 操作位置與行為

- **下架**：在「目前公告」選取公告，取消「發布到首頁」並按「儲存公告」；公告留在目前清單，可繼續編輯。
- **刪除**：選取公告後按「刪除公告」，核對標題並確認。公告移至「已刪除」清單，首頁與公開圖片網址不再提供該公告；尚未儲存的輸入不會保存。
- **檢視與還原**：切換「已刪除」，可唯讀查看本文、照片、內文圖片與「公告修改歷史」。按「還原公告」並確認後，公告回到「目前公告」，維持未發布；核對內容後才另外勾選「發布到首頁」並儲存。

已刪除公告不能修改本文或圖片，管理員仍可讀取保留媒體及歷史。刪除與還原需要管理 session、CSRF、明確確認及目前版本，公告與稽核在同一交易保存。同一操作以固定 request_id 綁定操作者與內容；連線中斷或結果不明時保留原請求並鎖住其他操作，可按畫面上的原樣重試核對結果。儲存及圖片重試也會核對回傳版本；若原操作後公告已被其他管理員變更，會保留目前輸入並要求重新選取核對，避免把舊圖片操作或舊回應套入新版公告。

既有比賽刪除／還原與報名資料保留流程繼續適用。本次沒有新增永久清除公告或比賽資料的操作。

## 資料相容與升級

新增 migration `0013_announcement_deletion`，前一版為 `0012_device_reports`。公告新增可空的刪除時間，既有公告保持未刪除，不補造歷史稽核；既有帳號、sessions、公告本文、媒體及其他資料保留。Python／npm 自身版本同步為 0.4.4，依賴版本不變。

**本輪未部署，現站維持0.4.3／`0012_device_reports`。** 升級既有資料須先停寫、成組備份並驗證，再透過 runtime guard 顯式執行 migrate 至0013；serve 不自動遷移。0.4.3／0012映像不能直接啟動新版0013資料。需要回復時，依[部署手冊](deployment.md)配對映像與備份並還原到新目標，保留故障庫，不直接降級目前資料庫。
