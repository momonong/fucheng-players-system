# 手機與桌面管理流程

本輪是前端操作改善，沿用 React、FastAPI 與既有資料／權限／交易；沒有 APK、PWA 快取、資料庫 migration 或公開部署變更。

## 使用方式

- 可用寬度 900px 以下預設「名單操作」，較寬畫面預設「完整表格」。兩個模式可手動切換；手動選擇在目前工作區優先，不因旋轉畫面被重設。平板也可依工作需要選擇。
- 名單以當次級數及既有格位順序顯示，列號對應完整表格，不重新分組。搜尋與級數篩選只改顯示；姓名相同時以辨識註記及順位協助選擇，所有操作仍用 registration ID。
- 點選選手後，可查看本場餐食／級數與歷次級數參考，再選欄底、交換、插入前後或指定空格。提交前顯示影響預覽；文字／合併格不列為可放人的空格。
- 精確格位、插刪行欄、文字／合併與底色保留在「完整表格」。桌面滑鼠／鍵盤與觸控選單繼續可用。保存完整安排、歷史、列印和 Excel 共用原有資料，與顯示模式無關。
- 小螢幕的會員及公告採清單／編輯兩個畫面；返回清單不卸載編輯器，可用「繼續編輯」返回同一份未保存輸入。切换螢幕尺寸也不重建編輯器。選擇其他資料、重新載入或離開頁面不屬於草稿永久保存功能。
- 報名管理使用適合觸控的名單與原生 modal 操作面板；寬畫面保留十級行政名單與頁內操作面板。手機先顯示報名名單，場次設定和刪除操作置於其後。
- 管理頁在小螢幕省略重複的公開導覽，保留管理分頁、球館首頁、會員分級與登出。安排工具可橫向捲動，保存與歷史排列在前。

## 保存與衝突邊界

手機選定來源時固定該版本的名單、布局及 state token。確認以既有 `useArrangementWorkspace` 送出 `swap`／`insert`／`move_empty`／`move_bottom`，沒有另一套資料修改 API。

處理中或結果未知時整場維持既有鎖定。回執及讀回成功後才關閉操作；未知請求保留既有 request ID／payload，由共用恢復入口重試。外來更新以服務端 409 拒絕，不自動改算目標或覆寫。歷史版與已結束場次唯讀；Undo／Redo 與完整保存仍使用服務端 receipt 契約。

## 隔離驗證

成品 `frontend/dist-mobile-workflows`、合成 DB `data/mobile-workflows-20261003-e2e.db`、初始測試 port 8072，後續各批使用獨立空閒 port。從未覆寫既有預覽或正式 Docker 資料。

使用與專案鎖版相符的 Playwright Chromium；瀏覽器暫存位於 `/tmp/fucheng-mobile-browsers`。核心測試 `frontend/e2e/mobile-workflows.spec.ts` 涵蓋點選操作、相同姓名、保存／歷史、復原重做、網路未知原樣恢復、外來更新拒絕、返回清單及跨尺寸保留輸入。尺寸含 360／390／430／768／1024／1440px。

完整批次短時間大量建立合成資料及查詢會觸發既有 ingress 限流，因此回歸採分批新啟動測試服務；不提高或關閉正式限流。瀏覽器模擬不是 Android／iPhone 真機驗收，軟鍵盤、安全區、實際手感仍需使用者確認。

### 2026-10-03 驗證結果

- 前端 typecheck、production build、`npm audit --audit-level=high` 通過，0 vulnerabilities；未更新套件依賴。
- 核心新流程：根路徑桌面／觸控 8 passed；相同成品在 `/fucheng` 下 8 passed。涵蓋同名識別、四種調整、保存／歷史唯讀、Undo／Redo、未知原樣重試、真實 409 與會員／公告草稿。
- 既有回歸採 22 個隔離批次，合計 38 passed：會員、報名／候補、公告圖片及尺寸、格位選單、歷史定位、保存列印／Excel、原生橫捲、拖曳與單雙擊。顯示切換的文字草稿保護完成後，另補原有外點保存／取消／組字／失敗保留 2 passed。不是宣稱一次全套測試通過。
- 第一輪環境缺少鎖版瀏覽器，安裝至獨立暫存後重跑。合併大批次觸發限流後，改以全新測試程序分批通過；沒有更動產品限流規則。舊會員測試的模糊 heading selector 改為 exact；既有格位測試明確切入完整表格。
- 實測發現成功 toast 擋住小螢幕管理導覽；改為底部可關閉提示且不攔截背景點擊，成功訊息短暫顯示。名單模式的歷史面板維持可見；切換模式不觸發隱藏表頭草稿的外點保存，原有可見表格外點保存仍通過。
- 全部使用合成資料；沒有操作真實會員、正式 image 或入口。Android／iPhone 真機、軟鍵盤及使用者手感驗收尚未完成。
