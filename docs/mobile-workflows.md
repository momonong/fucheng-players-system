# 手機與桌面管理流程

## 2026-10-05 手機整張選手方塊拖曳（尚未發布）

使用者要求長輩不必瞄準六點把手。本節取代下方 0.3.4 的窄畫面「滑姓名捲表、拉把手移動」規則；寬度大於 900px 的功能與樣式保持原狀，包含寬畫面觸控裝置。

- 寬度 900px 以下隱藏 ⠿，姓名按鈕填滿整個選手方塊；姓名、辨識註記及方塊四邊都能起拖，不必長按。移動超過 6px 才建立拖曳預覽，放手仍只採用已顯示的交換／插入／移至空格預告。
- 輕點選格、連點兩下開選手資訊。第一次接觸不顯示 ghost，避免清掉雙點紀錄。移動曾超過門檻，即使回到起點也不算輕點；取消、失去 capture、第二指介入均清理該次操作。
- 手機儲存格操作繼續從表格右上 ⋯ 開啟，觸控 contextmenu 不開選單。空白格／文字格保留原生捲動；拖曳接近表格邊緣可自動捲到遠端級數欄。
- `touch-action:none` 只套用可拖動的手機選手方塊。範圍選取、唯讀歷史與 unknown 鎖定不啟動拖曳；資訊與原有復原流程保留。桌面姓名／把手拖曳、右鍵、雙擊、鍵盤及樣式沿用原行為。

本輪沿用同一安排控制器、API、runtime 根路徑／`/fucheng` 支援與資料格式，沒有 migration 或依賴變更。隔離驗證及限制見 [驗收紀錄](acceptance.md#手機整張選手方塊拖曳2026-10-05尚未發布)。工程驗證不代表手機真機手感已獲接受，本輪未推送或部署。

## 2026-10-04 手機表格修正（0.3.4）

使用者真機回饋否決 0.3.3 的「名單操作」：需要直接在安排表內移動人員，且觸控拖曳不可被右鍵選單遮住。本輪移除替代名單與模式切換，沿用同一格位表、安排控制器、資料與權限。已依後續授權發布並部署 0.3.4，見 [家中部署紀錄](home-deployment.md)。

### 互動與驗收契約

- 手機直接顯示安排表。滑動姓名區可原生捲表；專用 ⠿ 把手至少 44px，按住後直接拉動，不等長按。移動超過 6px 才成為可提交拖曳；單純點把手不寫入。900px 以下加寬表格欄位及提供操作提示。
- 手機（窄畫面或最近輸入為 touch）的 contextmenu 只阻止瀏覽器選單，不開儲存格／表頭／軸選單。明確 ⋯ 仍可開啟工具；桌面滑鼠右鍵、Shift+F10 保留。拖曳中各選單關閉且不能重新開啟，避免遮擋落點。
- 拖到選手中央交換，上下邊界插入，空格直接移動；放手僅提交已顯示的預告。取消、失去 capture、第二指介入或 Escape 不提交。起拖保留原 token；外來變動以 409 拒絕。未知請求仍保留固定 request ID／payload，不能自動覆寫或重新計算目標。
- 保存、Undo／Redo、歷史唯讀、列印與 Excel 使用原本契約。文字／合併／底色及行列工具保留。會員與公告的手機清單／編輯頁、報名觸控面板也保留。
- 管理員名稱移到帳號工具列下方，與備份狀態同列、位於其右側；整組在桌面與手機均靠右對齊。備份狀態尚未取得時仍顯示名稱。
- 0.3.4 的素食名單入口與隊長顯示已收到後續調整需求，以下「素食名單後續修正」取代其顯示規則。姓名相同時附辨識註記；依 registration ID 對應，使用本場 diet，不受搜尋或素食高亮開關裁減。
- 歷史使用所選版 rows/layout；layout=null 不從目前安排或 legacy 顯示表推定隊名，diet=null 不補現況。

### 根因與協作審查

舊把手要求靜止 350ms，提前移動超過 8px 即取消，迫使用戶長按；把手 contextmenu 只 preventDefault，仍冒泡到 td 開啟選單。body portal 選單攔住 elementFromPoint，拖曳無法命中被遮住的格位。原測試等待 ghost 後才移動，未覆蓋快速起拖與 contextmenu。

回歸另捕捉到 Chromium 在失敗恢復後收到兩次 touch pointerdown/up、卻省略第一次 compatibility click。手機姓名改由未移動且未取消的 pointerup 計算單／雙點，略過 touch compatibility click；原生滑動、第二指及 cancel 會清除計數。桌面仍使用 click/dblclick。

本對話負責實作及整合，獨立唯讀 subagent 核對根因、事件隔離及資料邊界。審查另發現拖曳時 Shift+F10 可能留下延後開啟的選單，已將禁止開啟的檢查加入共用入口；軸選單測試也檢查其實際 group 面板。

驗證使用獨立 `frontend/dist-mobile-grid-touch`、`data/mobile-grid-touch-20261004-e2e.db` 及獨立 loopback ports；不用真實資料、不覆寫正式 image／預覽成品。結果見 [驗收紀錄](acceptance.md)。Chromium touch 事件、contextmenu 注入與視窗尺寸測試不等於 Android/iPhone 真機；Safari 原生長按、軟鍵盤及操作手感仍待驗收。

## 素食名單後續修正（2026-10-04，0.3.5 已部署）

使用者否決 0.3.4 的大型並排圖示，明確要求小圓形疊在「素食 x 人」右上角。本輪改為 28px 可見圓形、44px 觸控區，主按鈕保留足夠右側空間避免名單入口攔截文字點按。兩個按鈕保持獨立：主按鈕切換高亮，圓形只開啟唯讀名單。

名單每筆顯示姓名／辨識註記、隊名及本場級數／各層欄名。規則已由使用者確認：

- 讀取實際格位所在欄的所有 header 列標籤，依上到下排列，再附固定表頭的實際自訂名稱。一般「x 級」不重複顯示；空白自訂表頭不補造名稱。合併標籤依涵蓋欄位套用，文字可位於非 anchor 底格；同一跨列表頭只出現一次，不同層同名仍各自保留。
- 管理員填寫的隊名優先：同列自訂文字欄的最近左側非空標籤，沒有才找右側；跨列合併隊名對涵蓋列生效。一般級數格裡的文字備註不當隊名。
- 沒有上述隊名時，以同一 stable body row 中本場級數數字最小的選手當隊長。1 級最高，缺 1 級依序找 2、3 級；同級依報名順位。隊名為姓名最後兩字加「隊」，單字姓名保留該字。此推導只供顯示，不寫回資料或建立分隊。
- 分組依 stable row 與當前格位，不能按插入後的行號或舊隊長快取推定；跨列隊名合併不會自動把所有涵蓋列當作同一隊來推導隊長。
- 歷史只讀該版本 rows/layout，後續更名／移動不改舊版名單。無 layout 或選手位置缺失顯示隊伍未知，不補目前資料。

實作留在 `codex/roster-location-labels`，沿用既有資料與 API，沒有 schema／migration／依賴變更。新增解析與保存→改名→回看歷史測試；以隔離成品 `frontend/dist-roster-labels`、合成 `data/roster-labels-20261004-e2e.db` 驗證。證據見 [驗收紀錄](acceptance.md)。

本輪已依後續使用者授權合併並部署 0.3.5，來源、映像及資料保留證據見 [部署紀錄](home-deployment.md#035-素食名單與管理列排版部署2026-10-04)。
