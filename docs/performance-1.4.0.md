# 1.4.0 瀏覽器效能與即時名單設計

使用者已授權優化快取、站內切頁、重複查詢，測試後合併及發布版本／映像，交付保留帳號資料的球館PowerShell；另確認其他人的名單更新採約5秒同步。以下實作選擇由工程判斷，沿用現有React／FastAPI／Worker，不新增資料表或依賴。

## 行為及界線

- 只有具內容hash的編譯資產（JS／CSS／說明示範圖）可長期快取，HTTP 200／304、正確媒體類型、無Set-Cookie才採用。HTML、API、會員資料、登入、錯誤、真實公告媒體維持no-store。Worker須同步允許同一資產政策，仍是轉送代理，不移動資格／名額／正候補判斷。
- 公開首頁、會員、比賽、報名及說明使用History API導覽；保留可直接開啟／重新整理、root與子路徑、上一頁／下一頁、hash、另開分頁、下載及外部連結。進出管理後台維持整頁界線，保留管理寫入與未確認操作既有守門。
- 會員分級資料載入一次，姓名／註記／級數篩選、筆畫排序、統計交由瀏覽器。顯示與列印來自同一完整資料；列印前仍重讀。重複的同時公開GET共用在途請求，不持久儲存會員或報名資料，不快取認證／POST收據。
- 個人及雙打名單在可見分頁每5秒自動重讀；頁面focus／回到可見／手動更新立即重讀，背景暫停。不重疊輪詢，慢回應不覆蓋較新的回應。成功寫入後強制新GET，不共用寫入前的在途回應；雙打unknown／寫入／receipt recovery期間保留鎖與原payload，不觸發POST重試。
- 球館目前正式1.3.0，底層schema0015；新更新器須核對既有已完成1.2→1.3收據，再針對1.3→1.4備份／全表及媒體一致性／原帳號驗證。兼容Docker config／manifest ID、Tunnel缺省Health、Windows ACL合法Administrators owner；不初始化、匯入、還原、重設管理員、清除原卷或重開機。

## 驗收

- root與/fucheng瀏覽器：內部切頁無新增Document請求／JS重抓，返回及直接網址仍正常；修飾鍵／管理入口不被攔截。
- 會員初次單一GET；打字和級數篩選不發GET，兩個同名註記可搜尋，筆畫順序及未裁切列印保留。
- 兩個獨立公開瀏覽器／管理端：正候補與雙打狀態變更約5秒可見，報名成功立即同步、失敗保留、取消／遞補與關閉可讀；舊慢請求不能覆蓋新狀態，寫入不重送。
- 真實build資產的快取標頭與瀏覽器二次下載驗證，HTML／API／媒體／錯誤不可快取；Worker單元測試含Cookie及轉送身份守門。
- 完整後端、前端型別／建置／audit、相關桌機／手機E2E、隔離舊映像→新映像資料摘要／原帳號登入／備份／重啟；更新器mock與實際Docker模板／PowerShell傳參。
- 發布固定main來源、Git tag、Docker digest拉回與config核對。球館實機只由使用者執行交付指令；不以本機驗證冒稱現場升級。
